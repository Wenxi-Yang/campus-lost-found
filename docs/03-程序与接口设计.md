# 程序与接口设计

## 1. 架构

Vue2 + Element UI 负责界面和表单；Axios 发送 REST 请求。开发期 8080 代理/api 至 8081；部署时前端构建到 Spring Boot static 目录，由同一应用提供页面与 API。

Spring Boot Web → Controller → Store/JdbcTemplate → MySQL。Auth 统一校验 JWT 和角色；Input 统一进行文本、编号、选项和日期校验；ApiError 统一返回错误；Bootstrap 进行首次分类/管理员初始化。

采用 HS256 签名 JWT，role 为 user/admin。JwtTokens 通过 JJWT 校验签名、issuer、算法、过期时间和撤销状态；Auth 继续读取数据库核对启用状态和角色，非管理员调用管理接口返回 403。JWT 存入 HttpOnly、SameSite=Lax Cookie，不写入 localStorage；也支持 Authorization: Bearer。退出撤销当前 token 并清除 Cookie。有效期 1 小时，未配置 JWT_SECRET 时进程启动随机密钥，重启需重新登录。

写接口继续要求 X-Requested-With: campus 且不启用跨站 CORS。HTTPS 可配置 JWT_COOKIE_SECURE=true。BCrypt 编码器统一在 WebConfig 注入，默认 cost=10，可用 BCRYPT_STRENGTH 调整；随机盐嵌入哈希。SchemaUpgrade 在 Bootstrap 之前执行旧库字段升级。

## 2. REST 接口

正常返回 JSON 数据；失败返回 {message: 错误原因}。

| 方法       | 路径（前缀/api）          | 权限和用途                                                                     |
| ---------- | ------------------------- | ------------------------------------------------------------------------------ |
| POST       | /auth/register            | 游客：student_number,name,phone,password                                       |
| POST       | /auth/login               | 游客：account,password；学号或手机号                                           |
| GET        | /auth/me                  | 登录：当前账户                                                                 |
| POST       | /auth/logout              | 销毁会话                                                                       |
| GET        | /categories               | 公开启用分类                                                                   |
| GET        | /items                    | 公开分页；keyword,location,category_id,type,status,page,size；mine=true 需登录 |
| GET        | /items/{id}               | 公开详情；登录后返回联系方式                                                   |
| POST       | /items                    | 登录：发布物品                                                                 |
| PUT        | /items/{id}               | 本人或管理员：编辑进行中物品                                                   |
| PUT        | /items/{id}/status        | 本人或管理员：status=open/finished/closed；遵循状态流转                        |
| DELETE     | /items/{id}               | 本人或管理员：删除物品与其申请                                                 |
| POST       | /items/{id}/claims        | 登录：description，认领进行中的招领                                            |
| GET        | /claims/mine              | 登录：本人认领申请                                                             |
| DELETE     | /claims/{id}              | 本人：撤回待审申请                                                             |
| GET        | /notices                  | 公开当前有效公告；all=true 限管理员                                            |
| GET        | /stats                    | 公开物品总数、进行中与完结数                                                   |
| GET        | /admin/users              | 管理员：用户列表，无密码字段                                                   |
| PUT        | /admin/users/{id}         | 管理员：enabled=true/false；管理员不可停用                                     |
| GET        | /admin/claims             | 管理员：所有申请与特征说明                                                     |
| PUT        | /admin/claims/{id}/review | 管理员：status=approved/rejected,reply                                         |
| GET/POST   | /admin/categories         | 管理员：查询/新增，name,sort_no,enabled                                        |
| PUT/DELETE | /admin/categories/{id}    | 管理员：编辑/删除                                                              |
| POST       | /admin/notices            | 管理员：新增公告                                                               |
| PUT/DELETE | /admin/notices/{id}       | 管理员：编辑/删除公告                                                          |
| GET        | /admin/stats              | 管理员：待审数、用户数、按分类/类型/状态统计                                   |

物品写入字段：title,type,category_id,location,occurred_at,description,contact。公告写入字段：title,content,kind,item_id,category_id,enabled,published_at,starts_at,expires_at。发布用户与管理员 ID 由已验证 JWT 的当前用户决定，不接受前端指定。

列表响应：items 返回{rows:[...],total:N}；page 从 1 开始，size 上限 100，默认 12。用户列表、公告、申请与分类在课程演示规模下直接返回数组。

HTTP 400 输入或状态不正确，401 未登录/错误密码，403 无权限/禁用/请求头校验失败，404 无记录，409 唯一键或外键冲突，500 服务内部错误。异常日志仅在服务端记录，响应不包含 SQL 和堆栈。

## 3. 前端页面

使用 Hash 路由：/寻物大厅、/notices 公告、/login 登录、/register 注册、/mine 个人中心、/admin 管理后台。App 按路由显示页面；ItemEditor 负责发布与编辑；AdminPanel 负责管理；NoticeEditor 负责用途、关联和全部公告时间字段。

表格及表单通过普通文本插值展示，公告不渲染 HTML。搜索绑定参数，SQL 不拼接用户输入为语法。联系方式不出现在公开列表，申请证明不在公开 API 返回。

## 4. 补充接口和参数

- GET /api/claims/incoming：登录后仅返回本人发布物品收到的申请，含特征和确认信息。
- PUT /api/claims/{id}/confirm：仅对应招领人可操作，body={decision: confirmed 或 rejected, reply: 1~500 字说明}。确认后仍为 pending，等待管理员审核；拒绝改为 rejected。
- GET /api/items 增加 occurred_from、occurred_until 时间参数，格式 yyyy-MM-dd HH:mm:ss，按物品实际发生时间筛选，起止均包含边界。
- keyword 支持空格分隔的多个词（最多 8 个，总长 100 字），每个词都必须匹配标题或描述，支持中文子串；SQL 参数绑定并转义 LIKE 通配符。
- 管理员 approve 前要求 publisher_status=confirmed；拒绝不要求招领人先确认。前端 IncomingClaims 组件承载收到的申请及核对操作，管理员登录直接进入/admin。
