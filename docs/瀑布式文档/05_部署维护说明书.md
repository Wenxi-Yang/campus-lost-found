# 校园失物招领管理系统部署维护说明书

## 1 系统概述

### 1.1 部署目标与组成

本说明书面向项目成员和接手维护者，说明在本地 Windows 环境运行、在 IDEA 中开发、连接 MySQL、重新打包和更新工程的方法。本期不要求公网业务部署；GitHub 保存源码和文档，在线项目介绍页不承担注册和认领业务。

系统由 Vue2 前端、Spring Boot 后端及关系数据库组成。前后端分开开发，交付时将前端构建资源放入后端静态目录，合并为 release/campus-lost-found.war。运行完整包只需 Java 和所选数据库，不必再运行前端开发服务器。

### 1.2 环境清单

| 软件 | 版本或要求 | 用途 | 验证方式 |
| --- | --- | --- | --- |
| Windows | 本机已验证 | 本地运行与开发 | 启动脚本和浏览器 |
| JDK | 8，本机 1.8.0_504 | 运行和编译 Java | java -version |
| Maven | 3 | 下载依赖、测试和打包 | mvn -version |
| Node.js | 14.21.3 | 前端开发与构建 | node -v |
| MySQL | 8，本机验收 8.0.18 | 正式关系数据 | SELECT VERSION() |
| IDEA | 支持 JDK8 和 Maven 的版本 | 打开完整工程 | 导入 pom.xml |
| Workbench | 8 或兼容客户端 | 执行 SQL 与备份 | 连接目标实例 |
| 浏览器 | Chrome 已验证 | 使用系统 | 打开 8081 或开发 8080 |

H2 演示模式不等于 MySQL，但适合没有数据库密码时先查看完整功能。Node 和 Maven 只在修改和构建源码时必需。开发环境遵循课程压缩包中的版本，不能随意将 Java 或 Vue 主版本替换后声称已经兼容。

## 2 操作系统与工程准备

### 2.1 目录与打开方式

在 IDEA 选择 File → Open，打开 D:\作业\AAA-大四作业\web，根目录应能看到 pom.xml、backend 和 frontend。不要仅打开某个 .java、.vue 或 Word 文件来代替导入工程。Word 文档位于“提交材料/瀑布式文档”，用 Word 或 WPS 打开；IDEA 用于查看代码与运行程序。

| 目录或文件 | 作用 | 修改后是否需要构建 |
| --- | --- | --- |
| frontend/src | Vue 页面与组件 | 需要前端构建后才更新 8081 包内界面 |
| backend/src/main/java | Java 业务与接口 | 需要 Maven 打包或 IDEA 运行 |
| backend/src/main/resources | 配置、schema、静态资源 | 需要重新打包 |
| database | MySQL 初始化、升级参考、演示与检查SQL | 按脚本用途执行，不能盲目覆盖旧库 |
| release | 可运行 WAR | 使用 build.cmd 更新，不手改二进制 |
| .run | IDEA 共享运行配置 | 导入后选择配置运行 |
| .github/workflows | 自动构建及已有展示页配置 | GitHub 执行，不是本地启动按钮 |

### 2.2 IDEA 配置

File → Project Structure → Project SDK 选择 JDK 1.8，语言级别设为 8。Maven 工具窗口加载根 pom.xml。若未识别，右键 pom.xml 选择 Add as Maven Project。Settings → Build Tools → Maven 指定 Maven 3；项目 .mvn/settings.xml 为镜像设置，依赖缓存配置在 .mvn/maven.config，避免修改其他工程的全局环境。

后端选择 Backend-Demo 运行配置。若共享配置未显示，打开 backend/src/main/java/cn/campus/lostfound/Application.java，右键 Run，再在 Run → Edit Configurations 中将参数设为 --spring.profiles.active=demo，Working directory 设为工程下 backend。工作目录决定 H2 的 ./data 保存位置，变更工作目录会像换了一个演示库。

## 3 数据库部署

### 3.1 演示模式

安装 JDK8 后在 web 根目录双击 start-demo.cmd，保持启动窗口运行。浏览器访问 http://localhost:8081。示例管理员 admin / Admin12345，学生 20260001 / Student123。首次启动在 backend/data 创建 H2 文件及少量演示记录，重启保留该工作目录下的数据。

停止时在启动窗口按 Ctrl+C，等待进程结束。备份演示库前先停止程序，再复制整个 backend/data。不要把 H2 数据文件当作 MySQL 导入脚本，也不要把演示账号用于真实开放环境。

### 3.2 MySQL 新库初始化

在 Workbench 建立到自己的 MySQL8 实例的连接，确认主机、端口和账号。打开 database/init-mysql.sql 执行，建立 campus_lost_found 与五张表，字符集 utf8mb4。脚本使用 CREATE IF NOT EXISTS，不主动删除旧数据，但不负责把任意旧表结构升级成新结构。

启动前在当前 CMD 窗口设置实际连接参数。下面的文字是填写说明，须替换后再执行；不要把真实密码写进仓库。

```text
set DB_USERNAME=你的数据库账号
set DB_PASSWORD=你的数据库密码
set ADMIN_PASSWORD=首次管理员密码至少8位
start-mysql.cmd
```

默认连接 localhost:3306。使用其他端口时设置 DB_URL 为完整 JDBC 地址，例如 jdbc:mysql://localhost:13306/campus_lost_found?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai。管理员账号仅在没有既有管理员时初始化，后来修改 ADMIN_PASSWORD 不会重置已有密码。

### 3.3 密码未知与历史升级

不知道原 MySQL 密码时先使用演示模式，或联系安装者确认账号；Windows 管理员权限不等于数据库登录密码。本项目已在本机另建 MySQL8.0.18 独立 13306 实例做真实验收，没有重置或修改原 3306 实例。该独立实例的临时验收已经结束，不应把它写成长期运行的正式服务。

第一版项目库由 SchemaUpgrade 按列检查补充招领确认字段并迁移 student 角色，重复启动应幂等。database/upgrade-v2.sql 供尚未升级旧库对照，不能对已经补列的库重复执行 ADD COLUMN。升级前导出数据库，在副本试运行后再接入。

### 3.4 数据脚本与连接变量

| 项目 | 用途 | 注意事项 |
| --- | --- | --- |
| init-mysql.sql | 新库建表 | 不清库，不替代任意旧库迁移 |
| demo-data.sql | 演示/隔离验收数据 | 含公开演示账号，禁止导入真实业务库 |
| verify-database.sql | 只读计数和关联检查 | 先选择正确数据库 |
| DB_URL | 主机、端口、数据库与时区 | 保留 serverTimezone=Asia/Shanghai |
| DB_USERNAME DB_PASSWORD | 应用数据库凭据 | 使用项目专用授权账号 |
| JWT_SECRET | 固定签名密钥 | 至少32随机字节的Base64；不设置则重启失效 |
| JWT_COOKIE_SECURE | Cookie是否仅HTTPS发送 | 本地HTTP设false，HTTPS才设true |
| BCRYPT_STRENGTH | BCrypt计算强度 | 默认10，更改前评估性能 |

## 4 后端部署与完整构建

### 4.1 后端开发运行

IDEA 中运行 Backend-Demo 或配置了环境变量的 Backend-MySQL。确认 Run 窗口出现 Started Application 和 8081 端口启动日志，再在浏览器检查大厅。不要同时启动两个占用 8081 的实例。控制台出现 Access denied 应检查数据库账号，不应直接重置数据库或删除文件。

完整 WAR 可通过启动脚本运行。手动运行时先进入 backend，使演示数据位置与脚本一致：

```text
cd backend
java -Dfile.encoding=UTF-8 -Duser.timezone=Asia/Shanghai -jar ../release/campus-lost-found.war --spring.profiles.active=demo
```

### 4.2 重新打包

运行 web 根目录 build.cmd：安装锁定前端依赖、Vue production build、tools/copy-static.js 复制资源、Maven 测试与 package，最终更新 release/campus-lost-found.war。首次构建需要网络下载依赖；后续可以使用已有缓存。只有日志成功且 WAR 时间更新，才能把新包交给他人。

本项目有 18 项后端自动测试。文档修改本身不要求重复构建 WAR；修改程序或构建配置后应运行受影响测试，并在交付前完成正常构建。GitHub 的自动构建可作为另一环境验证，但不能代替本机实际访问验证。

### 4.3 可选外部容器

如课程要求外部 Tomcat，应使用 Tomcat9，将包以 ROOT.war 部署为根应用，并设置 MySQL 环境变量。前端接口使用 /api，部署在任意非根 context 下需要另做路径适配。该方式未在本次环境实际验收，不作为已经部署完成的成果。

## 5 前端开发与访问

### 5.1 开发服务器

在 IDEA Terminal 进入 frontend，首次运行 npm ci，再运行 npm run serve。浏览器打开 http://localhost:8080。vue.config.js 将 /api 代理到 8081，因此后端也要启动。直接双击 .vue 或 source HTML 不能运行完整系统。

```text
cd frontend
npm ci
npm run serve
```

修改 Vue 后可在 8080 看开发效果。8081 展示的是 WAR 内已构建页面，只有重新打包并重启完整程序才会更新。识别两种地址可以避免“已经改代码但页面没变化”的误判。

### 5.2 本地与其他电脑

localhost 永远指当前访问者自己的电脑。将工程复制到另一台电脑后，要在那台电脑安装 Java 并运行启动脚本。若多人访问同一个局域网实例，需使用运行电脑的真实局域网地址并核对防火墙；这不是本期必须验收的公网功能。

## 6 系统维护

### 6.1 更新与回退

更新前备份当前源码、release WAR 和数据库，记录 Git 提交号。源码开发先在隔离数据环境验证。停止旧实例，替换已验证 WAR，使用原工作目录和正确 profile 启动，再检查登录、搜索、认领和公告。若失败，停止新程序，恢复原 WAR；涉及结构变更时先核对数据兼容性，不能只换回程序而忽略数据库。

不通过删除 backend/data 解决登录或状态异常，否则会丢失演示记录。管理员清理物品会级联删除申请，应先判断能否仅关闭。分类有引用时采用停用，用户账号只启停，保留追溯关系。

### 6.2 数据库备份与恢复

Workbench 可使用 Server → Data Export 导出 campus_lost_found 的结构和数据。也可在有权限的终端使用 mysqldump，以交互方式输入密码，避免密码出现在命令行历史。文件按日期和版本保存，不提交含个人信息的备份到公开仓库。

恢复时使用新建的隔离库先执行导入，检查五表计数、用户唯一约束、外键、公告关联及批准记录，再切换应用连接。下列命令为操作范式，路径和账号须按环境修改：

```text
mysqldump -h 127.0.0.1 -P 3306 -u 项目账号 -p --single-transaction --routines --triggers campus_lost_found > campus-backup.sql
```

### 6.3 常见故障

| 现象 | 检查位置 | 处理 |
| --- | --- | --- |
| 8081启动失败 | Run或脚本窗口 | 检查端口占用，只停止自己启动的实例 |
| Access denied | MySQL连接变量 | 核对账号、密码和授权主机 |
| Unknown database | Workbench库列表 | 初始化正确的目标库 |
| 404或无法请求API | 访问地址与代理 | 开发8080需后端8081；完整包用8081 |
| 重启后未登录 | JWT密钥配置 | 随机密钥属于正常行为，重新登录 |
| 用户被拒绝访问 | 后台账号状态 | 核对enabled与角色，不手改页面绕过 |
| 公告不显示 | 公告管理的启用和时间 | 核对发布、生效、截止与机器时间 |
| 申请不能通过 | 招领确认与物品状态 | 先由发布者确认，核对pending和open |
| 修改前端后无变化 | 开发地址和WAR时间 | 看8080或重新构建WAR并重启 |

## 7 GitHub与本地同步管理

### 7.1 更新规则

后续正式修改同时维护 D:\作业\AAA-大四作业\web 和 Wenxi-Yang/campus-lost-found 仓库。文档、源码和脚本均包含在更新范围，PPT在另行要求前不改。每次更新先核对本地是否有用户新改动，避免用旧副本覆盖，再提交Git并推送，保留可回退记录。

不上传数据库数据目录、MySQL密码、.env、依赖缓存或 node_modules。WAR作为本地完整交付包，仓库自动构建可生成可下载运行产物。GitHub同步的源码和文档应逐文件核对SHA256；换行转换等差异要说明，不以“已复制”代替验证。

### 7.2 课程验收建议

先打开用户使用说明书演示完整闭环，再打开程序设计查看接口与加锁规则，最后在测试说明书查看验证结果。IDEA的工程树、启动日志及测试结果若需教师截图，按随附“工程与截图指南”逐项操作，截取真实运行信息并隐藏个人路径或凭据。
