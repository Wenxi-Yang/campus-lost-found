## 三、IDEA需要截哪里

### 图A 工程结构

1. IDEA选择File → Open，打开D:\作业\AAA-大四作业\web。
2. 左侧选择Project视图，展开backend/src/main/java/cn/campus/lostfound，显示Application、AuthController、ItemController、AdminController。
3. 同时显示frontend/src、database、docs或提交材料和根pom.xml，必要时折叠不相关目录。
4. 中间打开根pom.xml或Application.java。
5. 截左侧工程树和中间编辑区，能辨认前端、后端、SQL三部分即可；无需显示个人桌面。

用途：程序设计说明书中的工程结构与部署准备补充证据。

### 图B 后端启动成功

1. Project SDK选择JDK1.8；右上角选择Backend-Demo运行配置并点击绿色运行按钮。
2. 如没有共享配置，右键Application.java → Run，在Run → Edit Configurations里设置参数--spring.profiles.active=demo，Working directory指向web/backend。
3. 下方Run窗口滚到最后，找Tomcat started on port(s): 8081和Started Application。
4. 截图保留运行配置名称、启动成功文字和端口，不需要截大段依赖下载日志。

如果8081被占用，先确认是否已经有自己的演示窗口在运行，不要随意结束其他程序；可直接使用已有实例。

用途：部署维护说明书中的本地启动证据。

### 图C 18项自动测试

1. 左侧打开backend/src/test/java/cn/campus/lostfound/WorkflowTest.java。
2. 点击类名旁边绿色运行图标，选择Run 'WorkflowTest'；也可右键文件运行。
3. 等全部结束，下方测试窗口显示通过数量和绿色状态。
4. 展开几个测试名，尽量保留WorkflowTest类名、18项通过和失败为0的信息。不要只截单个绿色图标。

也可以在IDEA Terminal回到web根目录执行mvn test，截Tests run: 18, Failures: 0, Errors: 0, Skipped: 0及BUILD SUCCESS。首次需要下载依赖；此测试使用隔离H2，不要求原MySQL密码。

用途：测试说明书E01证据的个人环境补充。

### 图D MySQL运行配置

仅在你掌握实际数据库连接信息时补这张。Run → Edit Configurations → Backend-MySQL，显示工作目录、profile以及DB_URL中的数据库名和端口即可。DB_PASSWORD、ADMIN_PASSWORD、JWT_SECRET都要隐藏，不要把完整环境变量窗口直接截图发送。

你目前不知道原MySQL密码，不必为补图重置密码或清库，也不要把Windows管理员密码当成MySQL密码。本项目另建独立MySQL做过真实验证，原3306数据未修改。

## 四、数据库图在哪里截

### 图E Workbench五表和关系

1. 用已有授权连接打开MySQL Workbench，确认目标库是campus_lost_found或专用验收副本。
2. Schemas中展开目标库的Tables，应有app_user、category、item、claim、notice。
3. 若需要图形关系，菜单Database → Reverse Engineer，选择目标连接和目标库，完成向导打开EER Diagram。
4. 移动五张表，确保notice到发布者、物品、分类以及claim到用户、物品的关联线可见。
5. 截图包含五表名称和关系线，不含连接密码。不方便展开全部字段时，以清晰为先，正文已有54字段字典。

在IDEA中具备Database工具窗口也可查看表，但不同版本支持不同；Workbench是本工程建议的数据库管理工具。

## 五、如果要自己重截界面

浏览器访问8081，按“06用户使用说明书”的步骤操作。推荐顺序是：游客大厅→注册/登录→发布found→另一学生申请→发布者个人中心“收到的认领申请”→管理员“认领审核”→申请人查看已通过→管理员“公告管理”。长弹窗应截完整字段与保存按钮，必要时缩放浏览器或分两张，上下文不要断掉。

使用两个不同学生账号；不能认领自己发布的物品。不同角色可用不同浏览器或无痕窗口，避免切换登录后弄混身份。仅在演示数据中操作，不为了截图删除正式记录。若需要把你提供的新截图替换进文档，我会连同说明书和GitHub一起更新。
