# 讲稿补充材料对照与修改说明

## 1. 本次发现的差异和改动

| 讲稿内容                                         | 原程序                    | 补充后的实现                                                                                 |
| ------------------------------------------------ | ------------------------- | -------------------------------------------------------------------------------------------- |
| JWT 里保存 user/admin 角色，管理员接口校验 token | 使用服务端 Session        | 已改为 HS256 签名 JWT，role 为 user 或 admin；校验签名、过期时间、账号启用状态与数据库角色   |
| 认领申请发送给招领人，确认后处理                 | 学生直接提交管理员审核    | 新增“收到的认领申请”，招领人核对特征并确认/拒绝，确认后管理员才可批准                        |
| 按物品、地点和时间查找                           | 关键词/分类/地点/状态筛选 | 补充丢失/拾获时间起止筛选，关键词支持中文子串和空格分隔的多个词                              |
| 管理员和学生进入不同操作界面                     | 管理员登录后先进入大厅    | 管理员登录后直接进入管理工作台，学生进入大厅                                                 |
| BCrypt 随机盐和可调成本                          | 已有 BCrypt，固定默认成本 | 保持 BCrypt 随机盐，增加 BCRYPT_STRENGTH 环境参数，默认 cost=10；密码 UTF-8 长度限制 72 字节 |

## 2. 认领流程统一口径

提交认领 → 招领人确认 → 管理员审核 → 物品 finished，申请 approved。

招领人拒绝时申请直接 rejected，记录招领人说明和处理时间；不伪造管理员审核人和审核时间。管理员也可以直接驳回无效待审申请。通过时同一物品其他待审申请自动驳回，事务和物品行锁防止多人同时认领成功。

claim.status 仍保留 pending/approved/rejected 三种状态；新增 publisher_status 记录 pending/confirmed/rejected/legacy。legacy 表示升级前已处理、没有招领人确认记录的历史申请。

讲稿第 4 页说“管理员删除对应招领信息”，第 5 页和 PPT 又要求状态追踪。现统一为审核通过后完结归档，大厅默认仅显示进行中的物品；切换状态仍可查历史记录。管理员保留手动删除重复/无效数据的功能，不在正常审核时物理删除，避免丢失申请、统计和公告关联。

## 3. 搜索说明

当前实现为参数化 SQL LIKE，适用于本课程项目：输入“雨伞”可匹配“黑色雨伞”，输入“黑色 雨伞”要求两个词都出现在标题或描述中。可结合分类、地点、状态和实际发生时间区间。

没有声称已使用 FULLTEXT，也未引入独立搜索引擎；讲稿中的“打算/后续调整”保留为扩展方向。当前搜索没有中文语义分词、同义词或拼音检索功能。

## 4. JWT 和数据库兼容

JWT 使用 JJWT 库创建和验证，含 sub 用户编号、role、iat、exp、jti 及 issuer；不写入手机号、密码等敏感信息。浏览器通过 HttpOnly、SameSite=Lax Cookie 自动发送，接口也支持 Authorization: Bearer。有效期 1 小时，退出将当前 token 加入撤销列表并删除 Cookie。撤销列表为单实例内存状态；未配置 JWT_SECRET 时启动随机密钥，重启需重新登录。

JWT_SECRET 可配置 Base64 编码、至少 32 随机字节的密钥。不要使用数据库密码充当 JWT 密钥。HTTPS 可配置 JWT_COOKIE_SECURE=true。默认演示不需要新增环境变量。

旧版 role=student 自动迁移为 user。SchemaUpgrade 启动时检查认领确认字段，仅补充缺失字段，保留用户/物品/申请/公告数据；历史已处理申请标记 legacy，不补造确认时间。手动升级示例在 database/upgrade-v2.sql，应用已自动升级时不要再手动重复 ADD COLUMN。

## 5. 汇报时建议修正的表述

- “这些信息都加唯一索引”应改为“学号、手机号分别设置唯一约束”；姓名并不唯一，密码也不设唯一。
- “cost 次打乱密码”应改为“cost 控制计算成本，工作量随 2 的 cost 次方增长”；默认 cost=10。盐由 BCrypt 自动生成并嵌入哈希字符串。
- “申请等待管理员审核”补全为“先由招领人确认，再由管理员审核”。
- “确认后删除对应招领信息”改为“审核通过后将信息完结归档，保留追踪记录”。
- “目前使用 FULLTEXT”改为“目前使用支持中文子串的关键词匹配，全文检索作为后续扩展”。
- 数据库用户表实际名为 app_user，避开通用 user 名称；数据库仍为五张核心业务表，认领确认字段在 claim 中扩充。

## 6. 验证

本次后端 17 项集成测试已通过，包括 JWT 篡改、过期、角色不一致、退出撤销、招领人确认权限、未确认不能批准、确认时间、500 字拒绝说明、中文多关键词、时间区间及旧库无损升级；前端和完整运行包验证结果见测试报告。
