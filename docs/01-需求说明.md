# 需求说明

## 1. 范围与来源

根据用户提供的校园失物招领 PPT 与课程 PDF 实现。课程中的提问回复系统仅作为技术示例，业务按校园失物招领实现。用户另要求明确公告用途、关联公告数据表和增加时间条目。

## 2. 角色与权限

| 角色   | 功能                                                                                                                     |
| ------ | ------------------------------------------------------------------------------------------------------------------------ |
| 游客   | 公开物品浏览、关键词/分类/地点/类型/状态筛选、详情和公告；联系方式须登录查看                                             |
| 学生   | 注册登录；本人失物和招领发布、编辑、完结、关闭、删除；提交认领；确认收到的认领申请；查看本人申请和两步意见；撤回待审申请 |
| 管理员 | 全站物品维护、用户启用禁用、认领审核、分类维护、公告维护、数量统计和待审提醒                                             |

注册只能创建学生，不能提交 role 升级。后端每次受保护请求都会查询账户是否启用。学生不能修改他人发布或查看他人的申请列表。

## 3. 主要流程

1. 注册填写学号、姓名、手机号、密码，或使用已有账号登录。
2. 发布 lost（失物）或 found（招领），填写标题、分类、地点、实际发生时间、描述、联系方式。
3. 在大厅搜索和查看详情。游客详情隐藏联系方式。
4. 对 open 的 found 物品提交 10 字以上特征说明；不能认领自己的物品，同一人对同一物品仅保留一条申请，待审撤回后可重新提交。
5. 招领人在“收到的认领申请”中核对特征并确认/拒绝；确认后管理员才能通过，管理员也可直接驳回无效申请并填写意见。通过会同步将物品设为 finished，其余待审申请自动驳回。
6. 个人中心跟踪发布和申请状态。物品状态只向 open → finished → closed 或 open → closed 前进，不重新开启，避免认领状态矛盾。

## 4. 公告作用与补充要求

系统通知用于平台服务安排；招领提醒让学生进入相关物品或分类；认领结果用于经管理员确认的结果与交接说明。通知不是学生认领申请，不直接公开特征证明。

每条公告记录发布管理员，可选关联物品和分类。提醒及结果至少关联其中一项。记录发布时间、生效时间、截止时间以及创建/修改时间。首页只展示当前有效公告，后台可查看和修改全部公告。

## 5. 验收要求

所有输入在后端校验，SQL 参数绑定，密码 BCrypt 保存。认领审批使用事务和物品行锁，确保同一物品最多批准一人。保留明确错误提示、列表空状态、删除确认、待审状态和更新时间。

## 6. 讲稿补充

鉴权采用签名 JWT，role 为 user/admin。默认大厅展示 open 信息，审核完结保留记录。补充中文多关键词和发生时间区间筛选；全文索引属于后续扩展，当前使用 LIKE。完整对照见 07 文档。
